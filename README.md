# Duels2D — Bouncing Battle Simulator

Duels2D is a modular, zero-player 2D physics simulator designed for recording high-retention YouTube Shorts and TikTok content. Fighters clash inside a mobile-friendly 9:16 aspect ratio arena, bouncing off walls with perfect elasticity, exchanging damage, and deploying unique weaponry. The simulator features dynamic hit flashes, visual particle sparks, custom sprite crops, fighter-specific sound pools, and an in-game command developer console.

> **Naming convention:** This codebase is migrating terminology. What used to be called "character" is now called "fighter". Fighter definitions and assets live under `fighters/`; old names still exist in runtime code that has not been migrated yet. See the [refactor plan](docs/codebase-refactor-plan.md).

## 🚀 How to Run Locally

Because Duels2D is browser-native and has no build step, you can run it using any simple static file server:

### Option 1: Live Server (VS Code / CLI)
Run a quick HTTP server from the root of the project:
```bash
# Using Python
python3 -m http.server 8000

# Using Node.js / npx
npx serve .
```
Then open `http://localhost:8000` (or `http://localhost:3000`) in your browser.

### Option 2: Local File Loading
You can also open [index.html](file:///mnt/c/Users/uhabc/Documents/Web-dev/Duels2D/index.html) directly in your browser. Note that some browsers restrict loading local ES modules or assets via the `file://` protocol due to CORS policy, so running a local server is highly recommended.

## 📂 Project Structure

The codebase is organized into five top-level directories by role:

| Directory  | Role |
|------------|------|
| `src/`     | Runtime code — entity classes, engine orchestration, UI, bootstrapping |
| `config/`  | Hand-authored config values — physics settings, fighter roster, sound manifest |
| `assets/`  | Media assets — fighter sprites, projectile images, sound effects |
| `tools/`   | Developer-only utilities — character studio, sound manifest generator |
| `docs/`    | Technical deep-dives and planning |

**Current layout:**

## 🕹️ Controls & Console Commands

### Global Hotkeys
* **`Space`**: Pauses or resumes the simulator (only when the command input console is closed/defocused).
* **`/`**: Toggles the developer command-line input box.
* **`Escape`**: Closes/defocuses the command line.
* **`Enter`**: Executes the command typed in the command input box.

### Command Console Commands
Type these into the command bar and press `Enter` to run:
* **`start`**: Resumes or starts the current match.
* **`pause`**: Pauses the simulator loop.
* **`restart`**: Resets the physics world and re-spawns characters.
* **`select`**: Opens the sidebar Character Selection roster panel.
* **`studio`**: Navigates the browser to the Character Studio tool.

## ⚙️ Roster & Configuration Model

All gameplay parameters and character statistics are entirely data-driven, located under [config/](file:///mnt/c/Users/uhabc/Documents/Web-dev/Duels2D/config/):

* **Game configuration** ([config/game-settings.js](file:///mnt/c/Users/uhabc/Documents/Web-dev/Duels2D/config/game-settings.js)): Controls physics multipliers, collision cooldowns, generic volume levels, and arena border styles.
* **Fighters** ([config/fighters/](config/fighters/)): Each fighter has one file containing its stats, weapon, visuals, poses, hitbox, and dialogue. Shared values live in `defaults.js`.

See the [configuration guide](config/README.md) for the editing workflow and field examples. Validate changes with `node tools/validate-config.js`.

## 🛠️ Tooling & Asset Pipelines

### Character Studio
Tune sprite sizes and layouts without image editor programs. Open the developer console with `/`, type `studio`, and press `Enter` (or open [tools/character-studio/index.html](file:///mnt/c/Users/uhabc/Documents/Web-dev/Duels2D/tools/character-studio/index.html) directly).
* Load the character configuration.
* Adjust **Image Scale**, **Image Offset (X, Y)**, **Health Bar Offset**, and **Hitbox Width/Height** using sliders.
* Define custom **Image Crops** non-destructively to remove transparent paddings.
* Save changes back to the selected fighter's file under `config/fighters/`.

### Sound Manifest Generation
To avoid hardcoding sound paths in character configs, we compile a sound directory structure manifest. Run the generator script whenever you add or modify sound files:
```bash
node tools/generate-sound-manifest.js
```
This updates [config/sound-manifest.js](file:///mnt/c/Users/uhabc/Documents/Web-dev/Duels2D/config/sound-manifest.js) automatically with both character-specific and shared sound groups.

## 🎨 Asset Conventions (How to Add a Fighter)

1. Create a new directory: `assets/fighters/<fighter_id>/`.
2. Add your base idle sprite: `assets/fighters/<fighter_id>/sprites/<fighter_id>.out.png`.
3. (Optional) Add weapon pose sprites: e.g. `<fighter_id>-windup.png`, `<fighter_id>-slap.png` in `assets/fighters/<fighter_id>/sprites/`.
4. Projectile images go in `assets/fighters/<fighter_id>/projectiles/`.
5. Add sound effects under `assets/sfx/characters/<fighter_id>/<sound-group>/`. See [sound-asset-structure.md](docs/sound-asset-structure.md) for naming conventions and folder layout.
6. Run the sound manifest generator: `node tools/generate-sound-manifest.js`.
7. Copy an existing file under `config/fighters/`, add its script tag to the arena and Studio pages, then run `node tools/validate-config.js`. See the [configuration guide](config/README.md).
