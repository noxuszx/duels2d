# Configuration guide

Runtime behavior lives in `src/`; routine balance and presentation changes belong here.

## What to edit

| Change | File |
| --- | --- |
| Fighter stats, weapons, sprites, hitboxes, poses, or dialogue | `fighters/<fighter-id>.json` |
| Defaults shared by every fighter | `fighters/defaults.json` |
| Fighter load order | `fighters/index.json` |
| Overall speed, collision damage, sound volume, or arena appearance | `game-settings.json` |
| Damage and health text appearance | `indicator-settings.json` |
| Sprite crop, scale, offset, or hitbox visually | Character Studio |

`game-settings.json` → `rendering.scale` controls the canvas backing-buffer
resolution without changing the arena size or physics. `1` is native CSS
resolution, `2` renders four times as many pixels, and values up to `4` are
accepted. Higher values increase GPU/memory cost sharply; `2` is the recommended
starting point for 1080 × 1920 recording.

The typed runtime composer at `src/config/fighter-config.ts` applies these defaults and converts grouped fighter definitions into the flat objects expected by the runtime. `sound-manifest.json` is generated by `node tools/generate-sound-manifest.js`.

## Fighter JSON

Every fighter file references `fighter.schema.json`, which documents the supported structure and enables JSON-aware editors to provide validation and autocomplete.

```json
{
  "$schema": "./fighter.schema.json",
  "id": "exampleman",
  "name": "Example Man",
  "color": "#ffcc00",
  "combat": {
    "maxHealth": 1200,
    "speed": 8,
    "baseDamage": 125,
    "faceTarget": { "mode": "always" },
    "weapon": null
  },
  "body": {
    "radius": 34,
    "hitbox": { "type": "box", "width": 78, "height": 112 },
    "hitboxOffset": { "x": 0, "y": -15 }
  },
  "presentation": {
    "image": "assets/fighters/exampleman/sprites/exampleman.png",
    "imageScale": 2,
    "imageOffset": { "x": 0, "y": -10 }
  },
  "lines": {
    "ambient": ["Example line"]
  }
}
```

Only values that differ from `fighters/defaults.json` need to be included. `faceTarget.mode` accepts `never`, `always`, or `range`. Supported weapon types are `projectile` and `proximity-melee`. Values ending in `Ms` are milliseconds; values ending in `Frames` are render frames.

## Adding a fighter

1. Copy the closest fighter JSON file and make its filename match its unique `id`.
2. Add its assets under `assets/fighters/<fighter-id>/`.
3. Add its filename to the `fighters` array in `fighters/index.json`.
4. Run `node tools/validate-config.js`.
5. Open Character Studio for visual tuning and save back to the same JSON file.

The validator catches malformed manifests, duplicate or mismatched IDs, invalid ranges, unsupported modes and weapons, malformed geometry and poses, bad dialogue, missing weapon fields, and missing assets.
