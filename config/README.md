# Configuration guide

Runtime behavior lives in `src/`; routine balance and presentation changes belong here.

## What to edit

| Change | File |
| --- | --- |
| Fighter stats, abilities, sprites, hitboxes, poses, or dialogue | `fighters/<fighter-id>.json` |
| Defaults shared by every fighter | `fighters/defaults.json` |
| Fighter load order | `fighters/index.json` |
| Overall speed, collision damage, audio categories, or arena appearance | `game-settings.json` |
| Character sound cues, per-character volume, and per-cue volume | `sound-manifest.json` |
| Damage and health text appearance | `indicator-settings.json` |
| Sprite crop, scale, offset, or hitbox visually | Character Studio |

`game-settings.json` → `rendering.scale` controls the canvas backing-buffer
resolution without changing the arena size or physics. `1` is native CSS
resolution, `2` renders four times as many pixels, and values up to `4` are
accepted. Higher values increase GPU/memory cost sharply; `2` is the recommended
starting point for 1080 × 1920 recording.

The typed runtime composer at `src/config/fighter-config.ts` applies these defaults and converts grouped fighter definitions into the flat objects expected by the runtime. `sound-manifest.json` is generated by `node tools/generate-sound-manifest.js`; regeneration preserves cue settings such as volume, category, interval, and pitch variation.

## Fighter JSON

Every fighter file references `fighter.schema.json`, which documents the supported structure and enables JSON-aware editors to provide validation and autocomplete.

```json
{
  "$schema": "./fighter.schema.json",
  "id": "exampleman",
  "name": "Example Man",
  "color": "#ffcc00",
  "combat": {
    "maxHealth": 1200,
    "speed": 8,
    "baseDamage": 125,
    "faceTarget": { "mode": "always" },
    "abilities": [{
      "id": "shove",
      "trigger": { "type": "enemy-in-range", "rangePadding": 16 },
      "audio": {
        "windup": "shove-windup",
        "hit": "shove-hit"
      },
      "timing": {
        "cooldownMs": 1200,
        "windupFrames": 8,
        "activeFrames": 12,
        "recoveryFrames": 10
      },
      "actions": [
        { "type": "damage", "amount": 80 },
        { "type": "knockback", "forceMagnitude": 0.1 }
      ]
    }]
  },
  "body": {
    "radius": 34,
    "hitbox": { "type": "box", "width": 78, "height": 112 },
    "hitboxOffset": { "x": 0, "y": -15 }
  },
  "presentation": {
    "image": "assets/fighters/exampleman/sprites/exampleman.png",
    "imageScale": 2,
    "imageOffset": { "x": 0, "y": -10 }
  },
  "lines": {
    "ambient": ["Example line"]
  }
}
```

Only values that differ from `fighters/defaults.json` need to be included. `faceTarget.mode` accepts `never`, `always`, or `range`. Abilities combine a trigger, timing, and reusable actions such as `damage`, `knockback`, `dash`, `swing`, and `spawn-projectile`. A `swing` rotates `presentation.weaponIdle` from `startDegrees` to `endDegrees` around the fighter-relative `presentation.weaponPivot`; its damage and knockback occur when active frames begin. Values ending in `Ms` are milliseconds; values ending in `Frames` are render frames.

Ability `audio` hooks (`windup`, `active`, and `hit`) reference cue names in
`sound-manifest.json`. Effective playback volume combines the master, category,
character, and cue volumes, so two fighters can use different volumes for
their `idle` cues while sharing the global `voice` category.

### Audio profiles

Each character in `sound-manifest.json` has a character-wide `volume` and a
`cues` object. Cue `volume`, `intervalMs`, `cooldownMs`, and `pitchVariation`
are optional. For example:

```json
{
  "characters": {
    "exampleman": {
      "volume": 0.8,
      "cues": {
        "idle": {
          "category": "voice",
          "volume": 0.45,
          "intervalMs": 5000,
          "pitchVariation": true,
          "clips": [
            { "id": "idle-01", "path": "assets/sfx/characters/exampleman/idle/idle-01.mp3" }
          ]
        }
      }
    }
  }
}
```

Character cues override shared cues with the same name. Shared cues therefore
provide defaults such as `hurt`, while individual fighters can replace or
rebalance them independently.

### Multiple character sprites

Use Character Studio's **Sprite** selector to tune separate images for the
`idle`, `attackWindup`, and `attackActive` animation phases. Crop, scale, and
image offset are stored per sprite; hitbox, health bar, facing, and ability
settings remain shared by the fighter. The Image tab can add, rename, remove,
or change the file path of these sprites. A new sprite starts with the base
presentation values, then keeps its own crop, scale, and offset independently.

## Adding a fighter

1. Copy the closest fighter JSON file and make its filename match its unique `id`.
2. Add its assets under `assets/fighters/<fighter-id>/`.
3. Add its filename to the `fighters` array in `fighters/index.json`.
4. Run `node tools/validate-config.js`.
5. Open Character Studio for visual tuning and save back to the same JSON file.

The validator catches malformed manifests, duplicate or mismatched IDs, invalid ranges, unsupported modes and actions, malformed geometry and poses, bad dialogue, missing ability fields, and missing assets.
