# Configuration guide

Fighter JSON stores editable identity, balance, body, presentation, component,
move, pose, and named-form data. Character Studio edits and serializes the same
fields. Runtime behavior is implemented in TypeScript under `src/`.

Baby Man and Granny have active behavior blueprints. Other fighters keep their
configured art and stats and use the passive setup. Authored attack settings do
not execute until a blueprint equips the mechanics and a behavior uses them.
Common body, art, and stat settings still apply.

## Files

| Change | File |
| --- | --- |
| Fighter stats, components, moves, poses, forms, and dialogue | `fighters/<id>.json` |
| Shared defaults | `fighters/defaults.json` |
| Roster/load order | `fighters/index.json` |
| Arena, game speed, and rendering settings | `game-settings.json` |
| Shared and character sound cues | `sound-manifest.json` |
| Damage/health indicator appearance | `indicator-settings.json` |
| Sprite crops, hitboxes, aim geometry, and authored poses | Character Studio |

The typed config composer is in `src/config/fighter-config.ts`; component and
move setting types are in `src/config/component-settings.ts`. Fighter JSON uses
`fighter.schema.json`. `sound-manifest.json` is generated by
`node tools/generate-sound-manifest.js`.

## Fighter gameplay data

`combat.impactDamageMultiplier` scales damage from wall and fighter impacts after the
normal speed threshold and damage cap. It defaults to `1`; `0` grants collision impact
immunity, values between `0` and `1` grant resistance, and values above `1` grant
vulnerability. It does not alter wall bouncing, attack damage, or attack knockback.
Temporary contact policies can still disable
impact damage during an action. Baby Man sets this multiplier to `0`.

`components` holds settings for capabilities a fighter can equip. `moves` holds
move settings referenced by behavior code, including an optional `windupSound`
cue. Runtime admission consumes `cooldownMs`; timing/range/cue fields require
explicit behavior/component use and do not create an automatic phase sequence.
`forms` stores named component/move/pose data. The reusable `Forms` component
lets behavior select a form, but does not install or remove component handles:
definitions equip handles up front, and scripts decide which handles to use.
Within a named form, supplied `components`, `moves`, and `poses` maps replace
their whole base maps, so each entry needs its full required settings. An omitted map
inherits the base map. An explicit `{}` remains empty after Studio save/reload.
Component names and settings are defined in
`src/config/component-settings.ts`.

Declaring a winner does not stop the world or invoke projectile `onMatchEnd`
removal. Projectiles continue until their normal collision/lifetime/owner rules
remove them; reset and disposal clear the world. The retained `onMatchEnd` policy
is used only by explicit registry `retireMatchEnd()` cleanup.

```json
{
  "id": "exampleman",
  "name": "Example Man",
  "color": "#ffcc00",
  "components": {
    "dash": {
      "speedMultiplier": 4,
      "accelerationForce": 0.02,
      "endOn": ["fighter-collision", "wall-collision"],
      "maxDurationMs": 900,
      "hit": { "damage": 60, "knockback": 0.3 }
    }
  },
  "moves": { "charge": { "cooldownMs": 1800, "windupSound": "attackWindup" } },
  "forms": {
    "focused": {
      "healthRatio": 0.5,
      "components": {
        "dash": {
          "speedMultiplier": 5,
          "accelerationForce": 0.02,
          "endOn": ["fighter-collision", "wall-collision"],
          "maxDurationMs": 900,
          "hit": { "damage": 60, "knockback": 0.3 }
        }
      },
      "moves": { "charge": { "cooldownMs": 1200 } },
      "poses": { "attackActive": "assets/fighters/exampleman/sprites/focused.png" },
      "sequence": [{ "pose": "attackActive", "durationMs": 300 }]
    }
  },
  "presentation": {
    "image": "assets/fighters/exampleman/sprites/exampleman.png",
    "poses": { "idle": "assets/fighters/exampleman/sprites/exampleman.png" }
  }
}
```

The example uses placeholder asset paths and a cue name; add the corresponding
assets and sound cue before validating it as a real fighter.

The `projectile` component has a reusable runtime emitter and flight lifecycle.
Granny's blueprint equips an emitter and `SpriteAim`; its behavior follows a
target and yields a shot operation. `MeleeAttack` provides reusable range checks
and timed swings. Granny's behavior also sequences timed poses and enters its
transformed form when health reaches the configured threshold. These are explicit
script decisions; form data alone does not create automatic thresholds or phases.
In Granny's data, the rolling-pin strike deals 45 damage with a 1100 ms cooldown;
the transformed shotgun deals 90 damage, applies 0.12 recoil, and has a 1400 ms
cooldown. Windup, active, recovery, and transformation pose durations are also
configured in the move/form data.

## Validation

`src/config/schema-validator.js` implements the JSON Schema vocabulary used by
fighter config. The same validator is used by runtime loading, Character Studio,
and `node tools/validate-config.js`, with no additional schema package. The CLI
also checks cross-file assets, pose references, sound cues, component settings,
and summon IDs.

## Adding a fighter

1. Copy a nearby fighter JSON file and give it a unique `id`; add assets under
   `assets/fighters/<id>/` and add the JSON filename to `fighters/index.json`.
2. For passive practice-opponent use, no behavior registration is needed.
3. For active gameplay, create a definition and readable behavior under
   `src/content/fighters/<id>/`. Equip reusable components in the definition and
   keep character choices/action order in behavior code.
4. Register the completed blueprint in `src/content/manifest.ts`. Baby Man's
   wall-crawl sequence and Granny's attack/form sequence are working examples.
5. Open the fighter in Character Studio for visual and JSON tuning.

The simulation foundation and config model are described in
[`docs/architecture/fighter-architecture.md`](../docs/architecture/fighter-architecture.md). The [authoring guide](../docs/authoring/fighter-authoring.md) covers component/behavior
composition, and the [migration checklist](../docs/migration/fighter-migration-checklist.md)
records remaining gameplay and manual acceptance work.

## Audio and rendering

Character cues in `sound-manifest.json` can override shared cues and configure
character/cue volume, category, interval, cooldown, and pitch variation.
`game-settings.json` → `rendering.scale` controls Canvas backing-buffer
resolution without changing arena or physics dimensions. Values above native
resolution increase rendering and memory cost.
